核心结论

“宠物情感陪伴”有两条不同赛道：陪真实宠物，以及用机器人宠物陪人。AI Pet 应以前者为主线，吸收后者的情绪表达方法。

硬件很热，但不是 MVP 起点

Aura、WIMZ、PawMe、KitteCube、Pumpkii、ORo 都在做移动陪伴、摄像头、奖励和行为识别，但多数项目仍在早期。第一版押注硬件会把风险放到供应链、宠物安全和封闭 API 上。

成熟数据来自健康和家庭设备

FitBark、Tractive、Invoxia、PetPace、Petivity、Petcube、Furbo 这类设备更适合作为真实宠物数字分身的信号源：活动、睡眠、排泄、叫声、位置、生命体征。

情绪要解释，不要宣判

MeowTalk、PettiChat、CatsMe、Tably、Pemi 显示用户需要理解宠物，但“翻译”和“情绪识别”不能绝对化。产品应输出可能意图、证据线索和下一步照护建议。

人类情感机器人宠物

Moflin、aibo、Loona、EMO、LOVOT、Joy for All、PARO 主要陪人，但对人格成长、触摸反馈和非语言表达很有参考价值。

谨慎观察

移动宠物陪伴机器人

Enabot、VARRAM、ORo 等产品存在，但“完全自主 AI 宠物保姆”仍未成熟，第一阶段只吸收能力模型，不依赖硬件。

产品组 已存在形态 可借鉴能力 MVP 判断
Furbo / Petcube / PETLIBRO / eufy 硬件 + App + 订阅 摄像头事件、叫声、双向语音、投食、日记 优先抽象成 CameraEvent 和 DailyDiary

Petivity / PETKIT / Litter-Robot / SiiPet 猫砂盆/外挂摄像头 + App 体重、入厕、排便、排尿、粪尿视觉 猫模型必须把排泄和体重设为一等事件
MeowTalk / CatsMe / Tably / TTcare 移动 App / API 叫声解释、痛感识别、照片健康观察 只做“可能意图/风险”，显示证据和不确定性
Pawzy / Joii / Petriage / Buddydoc App/Web/诊所平台 档案、提醒、分诊、PDF、真人兽医升级 学习报告和分级路径，不做诊断式营销
Moflin / aibo / Loona / EMO / LOVOT 机器人宠物 + App/云服务 人格成长、触摸反馈、动作、长期依恋 借鉴表达系统，不偏离真实宠物数字分身主线

MVP 路线

本项目应把“真实宠物数据”转成“有证据的情绪状态”，再让桌宠表达出来，并触发任务和报告。

1. 多源输入手动记录、CSV、mock、未来 VendorAdapter：活动、睡眠、食量、饮水、排泄、照片、叫声。
2. 证据时间线把指标和观察统一成 HealthMetric、BehaviorEvent、Observation，保留来源和置信度。
3. 情绪解释输出可能状态、证据线索、反例和下一步。避免“确定翻译”和医疗诊断。
4. 桌宠表达OpenPets 气泡、动作、状态变化和主动 check-in，让真实宠物状态可见。
5. 照护闭环生成任务、库存提醒、训练建议、宠物主安抚和兽医可读摘要。

优先级矩阵

不是所有热点都值得马上做。第一阶段看可控性、可验证性和是否直接服务真实宠物数字分身。

现在做
  • OpenPets 视觉底座
  • 手动/CSV/mock 数据
  • 情绪证据解释
  • 照护任务和兽医摘要
第二阶段验证
  • FitBark API
  • Petcube / Furbo / PETLIBRO 事件
  • Tractive / Invoxia / PetPace 数据
  • MeowTalk / CatsMe 外部信号
先不做
  • 自研移动硬件
  • 自动投食/激光控制
  • 绝对化宠物翻译
  • 医疗诊断和处方建议

代表项目裁决

这里列出直接影响架构和产品取舍的项目。完整分项目卡片已写入 docs。

项目组 判断 本项目动作
OpenPets / codex-pet-companion / DyberPet 可控性最高，能支撑桌宠表达、MCP 控制和照护状态机。 进入 MVP 主线：OpenPets 做外壳，后两者抽 domain model。
FitBark / Tractive / Petivity / Catlog 最适合作为真实宠物数字分身的数据来源。 先按它们的指标设计 schema，第二阶段验证 API 或导入路径。
Furbo / Petcube / PETLIBRO Scout 成熟家庭陪宠入口，事件类型很适合日记和提醒。 把摄像头、叫声、动作、投食、双向语音建成事件模型。
MeowTalk / PettiChat / CatsMe / Tably 能满足“理解宠物”的强需求，但科学边界很敏感。 只做“可能意图/痛感风险”，必须显示证据和不确定性。
Aura / WIMZ / PawMe / KitteCube / ORo 方向正确但硬件风险高，适合观察不适合依赖。 把能力拆成虚拟任务和事件，不做第一版硬件实现。
Moflin / aibo / Loona / EMO 情绪表达强，但目标是陪人，不是照护真实宠物。 借鉴人格成长、非语言动作、触感隐喻和长期记忆。
