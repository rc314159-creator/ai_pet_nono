本次调研围绕 AI Pet 的真实宠物档案、照护任务、库存提醒、宠物用品推荐、订阅补货和未来 checkout 闭环展开。 结论不是立刻做大商城，而是先找出可复用的 commerce engine，并明确哪些项目只适合作为参考或反例。

最终判断

Shortlist

推荐短名单

Medusa

Rank 01 · TypeScript · MIT

与当前 React/TypeScript 主线最接近。Commerce modules 和 workflows 可承接商品、库存、订单、订阅和宠物档案约束。

建议做第一 PoC。

Saleor

Rank 02 · GraphQL · BSD-3

API-only 和多渠道能力强，适合把 AI 推荐、宠物档案、库存与前端渠道解耦；代价是引入 Python/Django/GraphQL 运维。

适合强 API 多渠道路线。

Vendure

Rank 03 · NestJS · GPLv3/commercial

TypeScript/NestJS/GraphQL 和插件系统很适合做宠物档案驱动的 commerce 定制，但 GPLv3 或商业授权边界必须先确认。

技术好，先审许可证。

Product Strategy

对 AI Pet 的落地策略

第一阶段只做推荐闭环

  • 商品推荐由照护任务、库存阈值、年龄阶段、过敏禁忌、健康约束触发。
  • 推荐卡必须解释为什么现在推荐、和哪只宠物相关、避开了哪些禁忌。
  • 不做自动购买，不把商品 feed 做成主界面。

第二阶段再接交易底座

  • 首个 PoC 用 Medusa：商品目录、库存阈值、订阅补货、mock checkout。
  • 如果走多渠道 API 平台，再对比 Saleor 与 Vendure。
  • WooCommerce 用作内容导购或独立小店，不承载长期核心模型。
