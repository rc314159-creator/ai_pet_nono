# 宠物情感陪伴与 AI 项目卡片

证据等级：A = 官网、官方文档、官方新闻稿、应用商店或公开仓库；B = 可信媒体、论文、行业媒体；C = 早期 landing page、众筹页或第三方目录；D = 只作为噪音/风险观察，不作为能力实证。

## 真实宠物 AI 陪伴硬件

| 项目 | 状态/证据 | AI 结合 | 情感陪伴能力 | 风险 | 对 AI Pet 的意义 |
|---|---|---|---|---|---|
| Tuya Aura / OMO Robotics | CES 2026 官方发布，证据 A | 多模态感知、宠物行为识别、异常提醒、自动移动、智能投喂 | 主动寻找宠物、语音互动、行为识别、离家陪伴 | 概念/预售期，硬件生态未验证 | 证明“主动陪伴 + 行为感知 + 投喂”是方向，但不适合作为 MVP 依赖 |
| OMO Robotics | 官网，证据 A/C | 机器人 + AI 宠物安全/情感支持 | 面向真实宠物的远程陪伴和互动 | 页面信息有限，商业成熟度待查 | 可作为硬件产品叙事参考 |
| WIMZ | 官网，证据 C | Edge AI、LLM、4K 摄像头、叫声/行为分析、多宠识别 | 移动跟随、语音播放、奖励逻辑、训练辅助 | 早期项目，学术/性能声明需复核 | “行为识别 + 奖励 + 隐私优先”的组合值得借鉴 |
| PawMe | 官网，证据 C | AI 互动、FPV 摄像头、激光、自动喂食/饮水 | 球形移动机器人陪宠物玩、远程看护 | 预售/交付风险 | 适合作为“硬件能力清单”，不适合第一阶段实现 |
| KitteCube | 官网，证据 A/C | AI companion robot、摄像头、双向音频、远程玩耍、投食 | 猫狗远程互动、叫名、激光、投喂 | 产品成熟度和 API 不明确 | 对本项目的“远程陪伴事件模型”有参考 |
| Pumpkii | 官网，证据 A | 2K 摄像头、移动、投食、激光玩具、智能看护 | 面向猫的移动摄像头/玩具/投食组合 | 更像智能摄像头玩具，AI 深度有限 | 可转化为 `PlayEvent`、`TreatEvent`、`RemoteVoiceEvent` |
| ORo / Ogmen | 官网，证据 A | AI 训练辅助、喂食、娱乐、安全监测 | 面向狗的陪伴、训练、运动、分离焦虑缓解 | 供货和长期维护待验证 | 提醒本项目把“训练任务”纳入照护日程 |
| Enabot EBO / ROLA | 官网，证据 A | 移动摄像头、AI 识别、自动投喂、语音互动 | 家庭成员远程陪玩、看护、移动巡航 | 强硬件闭环，开放能力有限 | 适合作为摄像头/互动事件来源参考 |
| VARRAM | 官网，证据 A | 自动移动、奖励投食、模式化游戏 | 宠物独处时的运动和奖励 | AI 能力较弱，偏交互玩具 | 提醒任务引擎要限制奖励频率 |
| Rocki | 官网/旧资料，证据 C | 移动、摄像头、激光、投食 | 远程控制陪玩 | 项目状态不稳定 | 作为历史样本，不进入优先级 |
| Companion / CV.Vet | 当前官网重定向至动物视觉 AI，证据 A/B | 从消费级狗陪伴机器人转向动物健康/福利 CV | 现已不再是消费陪伴机器人 | 产品 pivot，不能当作活跃竞品 | 说明硬件陪伴赛道商业化压力大 |

## 宠物健康、行为与情绪 AI

| 项目 | 状态/证据 | AI 结合 | 情感/健康能力 | 风险 | 对 AI Pet 的意义 |
|---|---|---|---|---|---|
| Invoxia Minitailz | 官网，证据 A | AI daily insights、活动/吃饭/睡眠/抓挠/吠叫/心率/呼吸 | 趋势提醒和健康洞察 | API 不明确 | 生命体征 + 行为 baseline 是数字分身核心输入 |
| PetPace | 官网/新闻稿，证据 A | AI smart collar、生命体征、疼痛/慢病监测、远程兽医 | 面向老年/慢病/术后宠物的早期提醒 | 医疗边界和合作门槛高 | 作为高价值但后置的医疗级 adapter |
| FitBark | 官网/API，证据 A | 活动、睡眠、健康指数数据；本身不强调生成式 AI | 行为趋势、活动目标、兽医共享 | 指标有限，不是诊断设备 | 公开 API 使其成为第二阶段优先集成对象 |
| Tractive | 官网/帮助页，证据 A | 活动、睡眠、静息心率/呼吸、吠叫、抓挠、AI 周报 | GPS 安全、健康趋势和提醒 | 非医疗设备，API 不稳定 | 适合定义消费级健康指标 schema |
| Whistle | 官网，证据 A | 行为数据、AI 洞察、粪便照片分析、Mars/Banfield 数据背景 | 活动/行为/粪便健康趋势 | 品牌/产品线状态需持续跟踪 | 粪便照片和纵向病历数据值得参考 |
| Maven Pet | 官网，证据 A | wearable + AI trend detection | 早期问题提醒、Vet-ready insights | 指标细节和 API 有限 | `baseline + delta + vet summary` 是本项目应采用的表达 |
| Catlog / RABO | 官网/官方新闻，证据 A | 机器学习行为分类、猫行为指纹、AI 兽医咨询 | 猫活动、休息、进食、排泄、压力/异常提示 | 猫个体差异大 | 猫模型应围绕个体 baseline，不用统一阈值 |
| Petivity / Purina | 官网，证据 A | AI 学习猫砂盆模式和多猫归因 | 体重、排尿、排便、入厕频次异常提醒 | 多猫识别和摆放环境影响准确率 | 排泄/体重应成为一等健康事件 |
| Whisker / Litter-Robot | 官网，证据 A/B | 多猫识别、SmartScale、入厕和健康 dashboard | 猫砂盆自动化和健康趋势 | AI 表述相对弱 | 适合作为猫设备数据结构参考 |
| PETKIT Purobot | 官网，证据 A | 摄像头识别、体重、尿液颜色/pH 等健康追踪 | 多猫健康识别、排泄异常提醒 | 硬件封闭 | 证明“视觉 + 猫砂盆”是猫健康强入口 |
| TTcare | 官网/应用页，证据 A | 照片识别眼睛、皮肤、关节、牙齿等异常 | 拍照健康检查 | 照片质量和误判风险 | 可作为 `PhotoObservation` 的非诊断参考 |
| CatsMe | 官网/App Store，证据 A | 猫脸痛感识别 | 痛感风险、健康跟踪 | 只能提示痛感风险，不能判断病因 | 痛感/舒适度可映射到桌宠表情和提醒 |
| Sylvester.ai / Tably | 官网，证据 A | 猫脸计算机视觉 + Feline Grimace Scale | 舒适度/痛感判断、是否看兽医 | 需要清晰猫脸，任务边界窄 | 高可信 AI 应选择窄任务和可解释量表 |
| MeowTalk | 官网，证据 A | AI 猫叫声解释，映射到多个意图/状态 | 帮宠物主理解猫叫情境 | “翻译”容易被误解 | 只应作为“可能意图”，不作为事实 |
| PettiChat | 官网/新闻稿，证据 C | 叫声录制、AI 解释、适应性学习、互动回应 | 宠物主与宠物“对话” | 众筹/早期，科学验证不足 | 可借鉴交互形态，不借鉴绝对化 claim |
| Pemi | 官网，证据 C | 宠物表情/身体语言情绪识别、知识库喂养建议 | 情绪识别、个性化喂养 | 证据和模型细节有限 | 情绪解释 UI 参考，不能作为验证依据 |
| Pawla | 官网，证据 C | AI pet care platform、记录和洞察 | 宠物主护理伴侣 | 早期信息有限 | 说明“宠物主陪伴 + 管理平台”是长尾方向 |
