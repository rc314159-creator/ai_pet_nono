# 宠物游戏与 AI 虚拟宠物项目调研

日期：2026-05-30

## 调研范围

本专题补齐“宠物游戏”和“AI 虚拟宠物”方向。已有知识库中已经有三份相关外部调研：

- 现有商业产品总览：[现有宠物相关商业产品调研](../existing-pet-products/INDEX.md)
- 健康/设备/兽医 AI：[AI+宠物健康项目调研](../ai-pet-health-projects-2026-05-30.md)
- 社区/丢宠/市场模式：[宠物社区与 AI 宠物生态调研](../pet-community-ai-ecosystem/INDEX.md)
- 机器人/桌宠/OpenPets：[机器人、虚拟宠物与开源桌宠项目逐项调研](../pet-community-ai-ecosystem/robotics-and-desktop-ai-projects.md)

因此本页不重复抄写健康设备和机器人项目，而是聚焦 25 个游戏、AI 虚拟宠物、人工生命和研究原型。长尾 App Store 克隆、只有关键词堆叠或缺少可信主页/代码/论文的项目只作为趋势观察，不作为 MVP 依据。

## 一页结论

1. **宠物游戏长期留存来自低摩擦日常循环**：喂食、清洁、玩耍、收集、装扮、任务和限时活动，而不是复杂剧情。
2. **AI 的真正价值不是“宠物会聊天”**：AI 必须改变状态、任务、记忆、健康解释或个性成长，否则只是聊天皮肤。
3. **Peridot 是重要反例**：AR、唯一宠物和繁殖很强，但公开信息显示其服务进入关停流程，说明技术亮点不能替代高频生活价值。
4. **Roblox 宠物经济证明收集/交易强，但不适合 MVP 主路径**：AI Pet 应先做可信照护闭环，社区和比赛只预留。
5. **最接近本项目方向的是“真实宠物数字分身”而非普通虚拟宠物**：应把真实宠物档案、设备/mock 数据、任务解释、桌宠表达和商品推荐连成一个闭环。

## 可直接进入 MVP 的设计模式

- 真实宠物档案驱动虚拟形象和任务，而不是随机生成宠物。
- 每日照护任务拆成可完成项：喂食、饮水、遛狗、清洁、梳毛、训练、用药提醒、伤口观察。
- 虚拟状态必须可解释：活动低、睡眠差、库存不足、抓挠多分别影响不同状态和任务。
- 桌宠负责“情绪表达和提醒”，Agent 负责“解释和工具调用”，Domain Service 负责事实状态。
- 商品推荐只能由库存/健康/任务触发，必须解释约束和禁忌。

## 适合二阶段

- 宠物繁殖/遗传/生成式形象。
- 社区挑战、排行榜、限时活动。
- AR/空间计算桌宠。
- 真实设备厂商 API 深度接入。
- 更拟真的个性学习和长期情绪模型。

## 不建议作为 MVP 主路径

- Roblox 式交易经济、抽卡稀有度和强社交货币化。
- 纯聊天 AI 宠物，没有数据闭环。
- Web3 token 作为核心价值。
- 医疗诊断、自动处方、自动下单。
