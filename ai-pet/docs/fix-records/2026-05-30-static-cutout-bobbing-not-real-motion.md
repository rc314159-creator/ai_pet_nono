# 静态宠物 cutout 上下晃动不是真实动作问题记录

日期：2026-05-30

## 事实时间线

- 用户纠偏：低保真程序化 3D 不真实，照片级 2D 平面也可以，但必须会动。
- 随后实现 `ai-pet/desktop-photo-pet/`，用 Electron 透明窗口显示照片级 Mochi cutout，并用 CSS 做呼吸、巡视、提醒、开心等动画。
- 用户再次指出：当前只是把一张宠物照片上下晃动，宠物本身没有真实地动起来，方向仍然错误。

## 证据引用

- 用户原话：“我要的不是一个静态的宠物图像。你现在做成的是把一张宠物照片给它上下晃动，但这个宠物本身并没有真实地动起来。”
- `ai-pet/desktop-photo-pet/styles.css`：上一版 `.pet-image` 的动画主要是整体 `transform`，没有对宠物本体进行头、耳、躯干、腿等局部运动。
- `ai-pet/public/assets/pets/mochi/mochi-corgi-realistic-v1.png`：当前资产是单张 cutout，没有拆分为可动画部件或多帧 sprite。

## 根因

把“照片级 2D 动态”实现成了整体图片 transform，没有建立宠物局部 rig 或多姿态帧。真实感要求高于简单 CSS 动效，必须让宠物身体局部产生动作。

## 修复计划

1. 废弃整图上下晃动作为主动作。
2. 经过后续用户纠偏，canvas/局部 rig 也不是当前 Demo 的正确主方案；四肢切片控制会显得怪异。
3. 当前修复方向调整为完整多帧动作包：每个动作由多张完整宠物帧组成，运行时只按 manifest 播放帧序列。
4. 当前先用 Mochi 生成走路 20 帧验证链路；后续照片上传链路应生成多姿态 sprite / motion pack，而不是只生成单张 cutout。
5. 知识库明确：桌宠“会动”至少要求动作序列本身变化，不能只是整张图片位移。
