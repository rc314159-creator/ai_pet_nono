# AI Pet 状态页未严格对齐参考项目交互问题记录

## 事实时间线

- 2026-05-31 01:15 CST，用户反馈状态页改造“压根就没有和参考项目对齐”。
- 用户指出参考项目状态页里的睡眠、活动等状态数据模块应可点击展开，而当前实现仅展示静态模块。
- 用户指出当前实现单位不统一，例如同一类时长出现“93分00秒”和“3小时33分”式混用，未按参考项目的“X时XX分 / X分XX秒”格式统一。
- 用户指出“异常历史”展开后的可操作性和参考项目不一致。

## 证据引用

- 参考原型 `docs/参考/status-page.html` 中，状态页包含顶部导航、快捷入口、宠物状态卡、日期条、睡眠/活动/休闲数据模块，以及左右侧滑面板。
- 参考原型 `docs/参考/status-page.html` 的异常历史卡片使用 `toggleAlert` 手风琴逻辑，展开后显示“具体数据”和“AI智能诊断分析”。
- 当前项目实现位置为 `ai-pet/src/App.tsx` 的 `StatusDataView` 与 `StatusDataModule`，上一版只做了数据模块静态渲染，没有实现睡眠/活动/休闲模块点击展开。
- 当前项目样式位置为 `ai-pet/src/styles.css` 的状态页样式，存在多轮旧样式遗留，交互状态样式不完整。

## 根因

- 上一轮修复把“参考项目对齐”理解成静态视觉结构对齐，忽略了用户强调的模块点击展开交互。
- 时长格式函数没有区分参考项目中“小时级模块”和“分钟秒级模块”的展示规则，导致不同模块单位口径不统一。
- 异常历史虽然保留了抽屉和卡片展开，但展开后的详情没有提供明确的二次操作入口，用户感知为“展开之后什么都点不了”。

## 修复计划

1. 状态页睡眠、活动、休闲三张数据模块改为整卡可点击展开，保留参考项目的三点按钮视觉，并加入展开箭头/展开状态。
2. 统一时长格式：睡眠和休闲总计使用 `X时XX分`，活动及休闲子项使用 `X分XX秒` 或整分钟 `X分`，避免 `93分00秒`、`54分00秒` 与 `3小时33分` 式混用。
3. 数据模块展开后显示对应模块明细、基线对比、趋势说明和可点击操作按钮。
4. 异常历史按参考 HTML 保持手风琴展开/折叠逻辑，展开详情只保留“具体数据”和“AI 智能诊断分析”。
5. 跑 TypeScript、构建和样式检查；如浏览器策略允许，再做状态页主页面和抽屉交互截图验证。

## 修复结果

- 睡眠、活动、休闲三张状态数据模块已改为可点击展开；模块标题区和子分类数据均可触发展开/折叠。
- 展开区域展示模块说明、关键明细和操作按钮；操作按钮会打开健康评估或异常历史侧滑面板，不再只是静态展示。
- 时长格式已统一为参考项目口径：小时级显示 `X时XX分`，分钟级整分钟显示 `X分`，有秒值时显示 `X分XX秒`；不再输出 `分00秒` 或 `小时` 混用。
- 异常历史展开后按参考 HTML 保留“具体数据”和“AI 智能诊断分析”，整张异常卡片可点击展开/折叠。
- 修复侧滑面板层级，避免健康评估/异常历史面板关闭按钮被顶部状态栏遮挡。

## 验证结果

- `npm run build` 通过，包含 TypeScript 构建检查。
- `git diff --check -- ai-pet/src/App.tsx ai-pet/src/styles.css ai-pet/docs/INDEX.md ai-pet/docs/fix-records/2026-05-31-status-page-reference-interaction-misalignment.md` 通过。
- 内置浏览器打开 `http://localhost:5181/?view=status` 验证：状态模块可展开/折叠；异常历史卡片可展开/折叠，展开内容保留“具体数据”和“AI 智能诊断分析”。

## 2026-05-31 追加修复

- 事实：用户再次反馈异常历史里展开后的箭头无法点击折叠，并指出页面结构仍未按参考 HTML 对齐。
- 证据：`docs/参考/status-page.html` 的异常卡片是 `.alert-card` 整卡 `onclick="toggleAlert(this)"`，`toggleAlert` 先折叠所有卡片，若当前卡片原本未展开才重新展开；展开内容只包含“具体数据”和“AI诊断区域”。
- 根因：上一版 React 实现存在 `useEffect` 自动把第一条异常重新展开，点击折叠设置为 `null` 后立即被恢复；同时异常详情里额外加入了“打开健康评估/继续观察 24h”按钮，偏离参考 HTML。
- 修复：移除自动重新展开逻辑，改为初始只默认展开第一条；异常卡片改为整卡点击展开/折叠；异常详情移除额外操作按钮，回到参考 HTML 的“具体数据 + AI 智能诊断分析”结构。
- 验证：内置浏览器打开 `http://localhost:5181/?view=status`，点击异常历史后第一条展开；点击展开卡片后 `expandedAlerts=0`，再次点击该卡片后 `expandedAlerts=1`；页面中 `status-alert-actions=0`。

## 2026-05-31 追加修复（二）

- 事实：用户继续反馈状态页仍未做到参考项目效果，特别指出参考项目中点击“心跳/心率”等指标会显示树状/柱状趋势图，而当前实现仍把交互错误地放在主状态模块的自定义展开详情里。
- 证据：`docs/参考/status-page.html` 的主状态页只保留睡眠、活动、休闲等数据卡片和三点入口；趋势图、维度分析、异常事件和健康建议集中在“健康评估报告”侧滑面板中。项目当前 React 实现一度把睡眠/活动/休闲卡片直接展开为自造明细，与参考结构不一致。
- 根因：上一轮把“状态栏可以点击”理解成主卡片内联展开，没有按参考项目的“主卡片入口 + 健康评估报告钻取图表”结构实现，导致用户点击心率类指标时看不到参考式趋势图。
- 修复：主状态模块恢复为参考式入口卡片，点击睡眠/活动/休闲进入“健康评估报告”；健康评估报告新增活动、睡眠、饮食、行为、心率、呼吸、体温指标切换，点击心率会切换到 7 日柱状趋势、AI 分析和均值/最高/最低明细；健康维度行也可点击切换对应指标。
- 验证：使用本机 Chrome headless CDP 打开 `http://localhost:5181/?view=status` 实际点击：健康评估面板可打开；点击“心率”后 active tab 为 `心率76 bpm基线 74 bpm`，趋势标题为 `心率趋势`，柱状图数量为 7，明细包含本周均值/最高值/最低值；点击主页面“睡眠”模块会打开健康评估并切换到 `睡眠趋势`；异常历史点击折叠后展开项数量从 1 变为 0。

## 2026-05-31 追加修复（三）

- 事实：用户再次指出参考项目已经给出足够内容和跳转，当前实现仍没有做出参考项目的丰富度与跳转路径；用户截图显示异常历史面板只有少量折叠卡片，视觉和内容密度明显少于参考 HTML。
- 证据：`docs/参考/status-page.html` 中异常历史面板包含 7 条异常事件，覆盖进食下降+抓挠、运动量偏低、夜间醒来频繁、饮水频率升高、舔舐频率异常、深夜异常活动、进食速度异常加快；每条卡片点击进入不同的“具体数据 + AI 智能诊断分析”。同一文件还定义了 `openHistory`、`openHealth`、`closeAllPanels`、`toggleAlert`、`switchWeek`、`renderWeek`、`animateHealthPanel` 等交互路径。
- 根因：上一版只补了抽屉和少量动态异常，未按参考 HTML 枚举完整异常事件和面板跳转逻辑，导致页面看起来像简化版而不是参考项目的可运行状态页。
- 修复计划：按参考 HTML 补齐 7 条异常历史事件；每条事件使用独立数据行和诊断文案；异常历史默认不展开，点击卡片才按手风琴逻辑展开；补齐健康评估打开、关闭、遮罩关闭、周切换和日历切换的可验证路径。
- 修复结果：异常历史已补齐 7 条参考式事件；第一条事件使用当前项目数据 `138g（基线 160g）`、`30分（基线 11分）`，同时保留参考式持续时间与 AI 诊断区域；异常历史默认 `expanded=0`，点击卡片展开，再次点击折叠。
- 验证结果：使用本机 Chrome headless CDP 打开 `http://localhost:5181/?view=status` 实测，异常历史打开后 `status-alert-card=7`、初始展开数为 0；点击第一条后展开数为 1、详情数据行数为 3；再次点击后展开数为 0；点击遮罩后异常历史关闭。健康评估打开后显示 `活动趋势`、7 根趋势柱；点击上一周切换到 `上周（5月16日 - 5月22日）`，点击下一周回到 `本周（5月23日 - 5月29日）`；点击日历首日后高亮从 `29` 切换到 `23`。
