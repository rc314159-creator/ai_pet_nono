# 2026-05-31 市集推荐页泄露推荐过程说明问题记录

## 事实时间线

- 宠物市集页顶部横幅显示“根据宠物档案、库存、抓挠记录和今日任务生成的演示推荐，共 6 条候选。”
- 用户指出该文案把系统推荐依据/推导过程直接写给用户，页面没有展示实际应该呈现的内容。
- 用户明确要求页面应该表达“最近出了什么问题，所以推荐什么东西”，而不是展示类似内部思路或演示过程说明。

## 证据

- 截图中市集横幅位于“今日照护推荐页”标题下方，直接显示推荐生成依据和候选数量。
- 代码位置：`ai-pet/src/App.tsx` 的 `MarketView` 中，横幅文案写死为“根据宠物档案、库存、抓挠记录和今日任务生成的演示推荐，共 {products.length} 条候选。”
- 同文件商品详情中多处使用“演示推荐：...”作为详情开头，进一步强化了演示过程口径，而不是用户任务口径。

## 根因

- 实现时把推荐系统的输入来源和 mock/demo 状态当成了页面说明。
- 市集页缺少“用户可理解的问题摘要 -> 推荐动作/商品 -> 注意事项”的展示层模型。
- 商品详情文案偏开发演示口径，没有收敛到真实宠物照护情境。

## 修复计划

1. 市集横幅改成面向用户的照护问题摘要，说明最近库存、抓挠、睡眠或散步场景中发生了什么。
2. 分类切换时显示对应分类的具体推荐主题，不再暴露“根据哪些数据生成”和“演示推荐”。
3. 商品详情改成“为什么现在推荐、怎么使用、有什么边界”的用户文案。
4. 保留商品卡片的简短推荐理由，但避免出现内部推导和 mock/demo 口径。
5. 用类型检查和浏览器截图验证市集页文案不再出现上述过程说明。

## 修复结果

- 市集横幅已改为按当前分类展示用户可理解的照护问题摘要，例如“先补货，再看皮肤”“先做局部清洁”“补同蛋白低敏配方”。
- 横幅不再展示“根据宠物档案、库存、抓挠记录和今日任务生成”“共 N 条候选”等内部过程说明。
- 商品详情已移除“演示推荐：...”开头，改为“今天为什么推荐：...”并补充使用边界，例如鸡肉过敏、7 天换粮过渡、破皮渗液不反复擦拭、保健品不替代兽医诊断。
- 切换市集分类时会收起已打开的商品详情，避免分类筛选后继续显示旧分类商品详情。
- 验证：`npm run typecheck` 通过；Playwright 打开 `http://127.0.0.1:5182/?view=market` 后检查全部、护理、主粮和商品详情截图，截图保存在 `/tmp/e2e-verify/ai-pet-market-copy-fix/`，未发现 console warning/error 或 failed request。
