# 2026-05-30 对话页 Agent 设计口径错误问题记录

## 事实时间线

- 用户确认对话页主 Agent 使用 OpenAI Agents SDK。
- 助手提出了“用户 + 宠物本人 + 系统卡片”的群聊结构，并把语音理解为“先生成文字，再固定 TTS 播放”。
- 用户纠正：该理解错误。对话页需要明确动物角色，Demo 阶段先固定群聊动物/宠物角色为“科技狗”；语音和文字是 Agent 工具/输出方式的区别，不是文字后处理；长期对话永远只有一个主对话且可多人参与；当前不需要过细安全边界。

## 证据

用户明确指出：

- 群聊身份中的动物角色必须设计清楚。
- Demo 先固定群聊动物/宠物角色为“科技狗”。
- 当前不需要细化安全边界。
- 永远只有一个主对话，但主对话可以多人参与。
- “让它回复语音，它就回复语音；让它回复文字，它就回复文字”，不是文字回复后再固定播放宠物声音。

## 根因

- 将对话页误解为普通双人聊天或“文本回复 + TTS 后处理”。
- 没有先把群聊成员、固定 Demo 用户角色、输出模态和工具调用边界讨论清楚。
- 过早进入实现，导致可能产生与产品口径不一致的 adapter 代码。

## 修复计划

1. 暂停对话页 Agent 代码继续推进，先对齐产品与架构方案。
2. 将对话页定义为“单宠物唯一长期主群聊”，支持多成员参与。
3. Demo 阶段固定群聊动物/宠物角色为“科技狗”，默认用户角色为“主人”。
4. 将语音定义为 Agent 可选择或被用户要求调用的输出工具；文字与语音是不同响应模式，不是固定后处理。
5. 后续实现前更新架构、模块或实施计划，确保 OpenAI Agents SDK、群聊 thread、memory 和工具调用设计一致。
