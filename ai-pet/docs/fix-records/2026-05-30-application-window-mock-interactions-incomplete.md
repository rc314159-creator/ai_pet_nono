# 2026-05-30 应用窗口 Mock 交互不完整问题记录

## 事实时间线

- 应用窗口已对齐参考 App 的欢迎页和五入口底部导航。
- 用户继续指出：即便当前使用 mock 数据，也不能只有静态展示；页面上的按钮应被设计成可点击状态。
- 当前市集分类、社区帖子、社区搜索、状态日期、健康报告、我的页中的毛发/妆容/配饰等交互仍未完整实现。

## 证据

用户明确举例：

- 宠物市集中的主粮、护理、玩具、保健分类都应该可点击。
- 市集不应写成“状态触发”逻辑，应有推荐页或推荐内容。
- 每个商品应配图片。
- 社区帖子应能点进详情，搜索应能实际过滤。
- 状态页日期应能切换，健康报告应能点进假的状态报告。
- 我的页中毛发、妆容、配饰也应有可点击 mock。

## 根因

- 视觉验收优先级过高，交互验收不足。
- 把 mock 数据理解为静态数据，没有把 mock 页面设计成可操作原型。
- 对参考 App 的分类、详情、搜索和报告跳转等基础移动应用交互没有逐项纳入验收标准。

## 修复计划

1. 市集页补齐可点击分类、推荐内容、商品图片和商品详情 mock。
2. 社区页补齐搜索输入、过滤结果、帖子详情 mock。
3. 状态页补齐日期切换和健康报告详情 mock。
4. 我的页补齐服装、毛发、妆容、配饰分类和可点击选项 mock。
5. 用 Playwright 覆盖上述点击路径，并归档截图。
