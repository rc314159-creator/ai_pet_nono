## 产品判断

2026-05-30 会议后，总产品定位扩展为 AI 情感陪伴型宠物产品；宠物形象用于承载 AI 陪伴、真实照护解释、虚拟养成和商业推荐。详见 [AI 宠物产品定位与讨论框架 2026-05-30](../product/positioning-framework-2026-05-30.md)。

当前 Demo 优先跑通已有真实宠物用户的主路径，但产品闭环不是在真实宠物数字分身和 AI 电子宠物陪伴之间二选一。电子宠物可以是完全虚拟的，也可以是真实宠物在系统中的分身。

用户价值来自三件事：

1. 真实宠物数据驱动虚拟形象和状态。
2. 用户点击桌宠进入应用窗口后与虚拟宠物互动，并把真实照护任务变成可执行清单。
3. 基于宠物档案、健康/活动数据和库存状态，给出问答、提醒和商品推荐。

## Demo 必须包含

- 宠物档案：物种、品种、年龄、体重、性别、绝育、过敏、病史、饮食偏好、外观特征、照片引用。
- 虚拟宠物：至少支持猫/狗两类形态，能显示状态、表情、气泡、简单移动或互动。
- 桌面宠物：必须启动系统级 OpenPets 桌宠窗口，并能由 AI Pet 状态触发气泡发言、异常提醒和状态反应；只有独立应用窗口、浏览器舞台或静态展示页不满足 MVP。
- 应用窗口：点击桌宠后弹出，默认进入陪伴对话主页，提供数据与异常、换装/互动等导航。
- 数据绑定：支持无设备手动记录，也支持接入 mock 设备数据。Demo 不等待真实项圈/手环 API 审核。
- 每日任务：喂食、换水、遛狗、清洁、梳毛、洗澡、训练、用药提醒、伤口观察。
- AI 问答：围绕这只宠物的数据、异常和记忆回答，不做泛宠物百科。
- 异常报告：由进食、运动、睡眠、定位或特殊行为异常触发，展示 AI 分析和处理建议。
- 换装/互动：使用内置装扮模板，结果同步到对话主页和桌宠。
- 库存和推荐：粮、零食、清洁、猫砂、药品、玩具库存不足时触发推荐入口；当前不阻塞 MVP。
- Agent 接入：涉及 AI 的能力优先接 OpenCode SDK / opencode runtime 或等价成熟 agent，不从零写 agent。
- 多端入口：桌面宠物和点击后弹出的应用窗口必须同时具备；其他端口后续讨论。

## 当前不作为核心闭环

- 大型社区和比赛体系。可以预留事件和排行榜字段，但不作为当前核心开发目标。
- 复杂 3D/VRM 宠物。当前可用 sprite pack 或 Live2D 样板，不让形象制作阻塞主闭环。
- 自动下单。当前先做推荐和确认入口。
- 完整多设备厂商适配。当前做 adapter 接口、mock 数据和手动数据。

## 成功标准

- 用户创建一只真实宠物档案后，系统能生成或选择一个匹配的虚拟宠物形象。
- Demo 启动后先看到系统桌面宠物窗口；桌宠能展示来自当前宠物档案、任务或健康状态的提醒，并承担点击展开应用窗口的核心入口职责。
- 点击桌宠后能弹出应用窗口，默认进入陪伴对话主页。
- 用户能和虚拟宠物进行至少 5 类互动：聊天、喂食、玩耍、清洁/护理、查看今日任务。
- AI 能基于档案和最近数据生成今日任务、异常解释和建议，并解释原因。
- 用户能应用一个装扮模板，且结果同步到桌宠。
- 库存不足时，AI 能给出约束明确的商品推荐，例如“幼犬、肠胃敏感、当前主粮剩余 2 天”。
- 桌宠窗口不是我们从零写的，而是基于可运行开源底座改造。
